# Description 
# -----------
# This file define the permission for all clients who connect th server (connected by user/passwd or cetiticate) in order to allow some rights.
# with these rights, they can or not call some methods associated with the namespace of these methods.
#
# **************************************************
# first information (enable/disable the check permission):
# **************************************************
# if this tag is disable(0), the server will no check. All users after authentification can call all the methods. 
#   - even when the LocalAccess datapoint is setting 
# if this tag is enable(1), the server will check with 2 levels of permission.
   level n°1 : the server check if the user have the right to call this method (3 level of method are define in MOS : User/Expert/Debug)
   level n°2 : the server check in addition if the user have the right to call methods when the localAccess is activated.
#
#
# **************************************************
# second part of file : definition of the rights for each users.
# **************************************************
# syntax : <name of user> : <rights definition>
#    <name of user> --> according with the name of the client who connect the server (user/passwd or certiticate)
#    example of name of client : TCU / caco / shifterGUI / JL_Expert / Daniel_Expert....
#
#   <rights definition>
# The definition  is define as 1 integer with differents flags (1 flag by 1 bit) --> use decimal not hexa value
# LocalAccess : bit n°0 -> allow or not the user to call methods when the server is on localAcess.
# User        : bit n°1 -> allow or reject the method in the namespace 2 (this is the default namespace for all methods)
# Expert      : bit n°2 -> allow or reject the method in the namespace 3 (if specify in the XML MOS file --> not define in the ICD and no generated by the codegenerator)
# Debug       : bit n°3 -> allow or reject the method in the namaspace 4 (internal MOS Method : like 'killOPCUA' )
# 
# example : JL_Expert : 15 --> "Debug" (bit n°3=1): "Expert" (bit n°3 1) : "User" (bit°2=1): "LocalAccess" (bit°1=1)



# not only 1 permission.txt file but 2 files ?
#  -> 1 file is defined directly in the MOS distribution $MOS_PATH/../properties/permission.txt (don't touch this file) or only if you have some general users/rights to defined for all MOS projects.
# 
#  -> 1 file define in your folder where you start the MOS. 
#
# The 2 files are using, so they are a concatenation of all the users/rights.
# If the same user are define in the 2 files, the file in your local folder replace the rights define in the $MOS_PATH/../properties/permission.txt files.
